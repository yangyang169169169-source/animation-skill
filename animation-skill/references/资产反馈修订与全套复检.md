# 资产反馈修订与全套复检

步骤2—4处理用户对已有资产的反馈、新样张确认、批量更新或交付后复检时读取。沿用现有规划／调用表、生成记录和最终索引，不新增制作阶段、逐图审批或固定测试配额。

## 1. 最新确认按维度生效

- 从本轮与仍有效的历史决定中分别确定身份／体量、发型／毛流、衣装／配饰、表面质感、光影／色调及构图标准；注明实际参考图和控制范围。用户只认可毛羽，不等于认可蓝紫边光；认可发型，也不等于要求复制那套衣服。局部新要求覆盖受影响维度，其余合格设定继续使用。
- 用户明确“这个可以，以此为标准”时，直接将该图登记为对应维度的当前基准，不重复要求确认。同人派生实际输入本人最新有效母版；原服装可用上一版该套衣装控制，避免把首套服装复制给所有造型。其他人物只借用户要求的材质／光色，保留自身脸身与发型。
- “先输出一个造型确认”只做该样张和必要修正，放资产目录外；用户确认后按既有授权更新依赖。确认仅确立标准，不凭此推断新一轮全剧生图授权；已授权的“确认后更新全部”无需再问。没有明确人工确认要求时，仍按原有助手静态验收扩展，不强加样张等待。
- 只修某套裙摆或配饰，不让同人全部衣装失效；身份或主发型改变才检查该身份依赖。用户明确统一全员质感时覆盖授权全员，但不顺带给已合格角色重新设计服装。阶段姿势、伤势、权限徽记和剧情证据保留。
- 用户明确改变身体拟人程度、种属或世界生活方式时，按[物种生活方式与世界联动设计](物种生活方式与世界联动设计.md)识别人物、场景和道具的真实联动依赖，旧母版不再锁定已被覆盖的维度。先看方向的授权只做指定样张与必要修正；整体方向获肯定不冒称每项细节、剩余全剧或动态使用均已通过，不自动重制全套。原关系、年龄、能力、动作因果和知情顺序保留，已授权替换不重复问。

## 2. 将审美反馈转成可见修改

- 发型同时检查辨识度和自然衔接。保留用户认可的主轮廓、分缝／起势、主束方向与节奏；“顺滑”主要整理根部、额角／鬓侧、主束与短绒过渡和冗余碎束，不把有记忆点的发型压回平庸贴头短发。主束有序叠压、连续生长，无悬空羽片、硬楔、孤立台阶或无依据的左右赘束。正面、三分之四和特写对应。
- 毛羽精细度与光色分开控制：保留分区绒层、中层分组和关键纤维，按用户确认回到柔和暖中性光和准确本色；去明显蓝／紫轮廓染光，不顺手抹掉原有妆色、虹膜色或服装固有色。其他指定风格按其画法落实。
- 服装丰富靠剪裁、廓形、层次、面料、纹样和场合变化共同成立。按[色光与材质基准](色光与材质基准.md)落实剧情优先的色彩层级：过浓过花的衣料适度降饱和、提明度，主配角放一起自然协调；舞台、礼仪和剧情焦点仍可鲜艳，不全员灰淡或泛白。男主造型同样有阶段差异，不只更换同一制服颜色；连续同场仍保同衣，不强定套数。
- 合适的女性华服／礼服可用与领口、发型及材质协调的项链、发饰等少量配饰；数量、佩戴侧别和阶段条件明确。朴素劳动装不机械加珠宝，配饰不遮住身份特征或取代剧情信物。用户要求成年角色增加露肤度时，按场合／人设调整肩颈、领口、袖型等，保留覆盖、运动结构与规定体型，不套到儿童或全部女性。
- 角色区分不足时，按[角色剧情驱动与造型差异](角色剧情驱动与造型差异.md)先比较主要角色、重点配角与常同框功能角色的脸身、头部轮廓、自然色区和个人识别组合，再选择适合男女角色的日常／职业配饰。保留用户明确确认的身份维度；不只加镜、换发型、换衣色掩盖相同底子，也不擅自重做已认可的主角。新设计通过后同步授权范围内该人的实际换装依赖，登记配饰数量、侧别和摘戴条件。
- 用户指出前几套几乎相同时，先核对是不是同一件衣物。相同衣物合并母版和集场调用，必要修补／升级保状态或细节；真正新装才落实有理由的可见设计差别。依[资产规划与按需生成规则](资产规划与按需生成规则.md)同步当前引用，不为保留已有数量故意加色添饰，也不把全部相近服装机械合并。
- 主角吸引力按人设落实：用户要求青春柔美、清纯可爱或英俊有神、威严时，用适度的眉眼、眼睑、头脸节奏、发型和姿态实现。轻微放大眼睛仍保原年龄、性别气质与面部结构，不把所有男性画成同款长睫美人，也不为可爱改成年体态。物种足掌／翼臂及必要连接不能因精修或鞋型变成人类结构。

## 3. 全套检查内容与需求覆盖

用户要求“全部／所有／更新后再检查”时，范围包括本轮授权全套和实际受影响依赖。逐张实际看图；再按同一身份跨装、同图多格并看。未实际看过的不能记内容通过，未检查完成就列真实剩余范围。

1. 对照权威正式稿、人设和当前需求／调用表，从第1集到末集核对实际可见人物、换装和必要状态。主要角色覆盖各自出场，不机械要求每人每集出现；回忆、照片、纯提及和画外音按实际资产用途区分。已有逐场台账在源稿及场次不变时可复用并核验，说明复用，不谎称重新全文通读。
2. 内容查身份、年龄、体量、发型、毛流、五官、服装和部位连接；固有色区／纹样、个人眼镜及职业配饰查同人三格与跨装，发饰、戒指、徽章、项链查数量、角色自身左右和阶段／摘戴条件。明确是同一人的跨岗位／婚礼身份继续同脸；群体中不同代表不因同一组编号强行同脸。另按主要关系组并看头像和完整身体，检查颜色协调与实际外貌区别；不能只用文字差异表判通过。
3. 对完整角色板，按既定格式核对正面完整形态、真实三分之四完整形态、完整头部＋短上颈／真实身份核心近景。完整头冠、喙尖、裙尾、头纱、鞋及必要辅助设备留在画内；两全身相同尺度且彼此分开，外轮廓有清楚留白，不能只删掉必要元素来避裁边。保持住院、康复或其他真实支撑姿态，不强迫站立。用途明确的局部／状态板按自身用途验收，不补成多余三联。
4. 场景复检同时查视觉身份与情绪：同类地点在布局、地标、材料与使用者／地域细节上是否可辨，当场影调是否服务剧情、真实时段与灯源，冷调或暗部的关键动作／表情区是否仍可读；同场不同视角保固定空间，不用换房间表达情绪。再查必要视角、空场及计划镜头信息。道具按实体、数量、接口／断口、文字与证据状态；场景／道具必要英文按[文字规则](场景道具英文文字规则.md)逐项查来源、字串、拼写／数字、位置、当前状态与信息时机，不能因含英文判错或把无依据装饰字留下。看用途、实际清晰度和主次，不用统一滤镜／材质掩盖结构错误；原有规格和原生文件规则继续。
5. 核对缺失、内容重复和多余元素。不同衣装用途要能说明；相同字节可由哈希检出，语义冗余仍须看图和剧情判断。文件存在、提示词已更新或数量吻合都不等于内容正确。

世界方向改变时，复检还要跨三类并看身体与服装的动作余量、生活通路、家具承托及工具接触点，查旧世界残留。只维护Skill时不把此项展开为项目复检或生图。未锁定的纯美术差异如决定采用，应登记实际选择并同步授权依赖；已锁侧别、数量或剧情证据出错必须处理或报告，不能把Prompt原要求、实图结果和用户认可混为同一事实。

## 4. 修复、复看与最终版交接

- 在本轮修改／补图授权及[生成记录与恢复](生成记录与恢复.md)的有限次数内，定位根因，用内置编辑或补生成处理受影响项；保留身份、剧情状态和质量。修复返回后实际查看目标问题与相邻区域，核对未引入换脸、发型漂移或新漏项；合格立即停，不重画其余合格图。明确只检查不修改时按只读范围交付问题。
- 以当前Prompt生成条目前的完整标题命名最终图片；免生成状态、局部图和复用分别统计。同步Prompt、当前索引、看图页和下游引用，记录真实输入版本／哈希；历史回执保留当时事实，不能把被同名替换的新图冒充旧输入。看图页指向当前图，必要时更新缓存版本标识。
- 三类资产文件夹只留每项一个当前最终图，无候选、过程、旧版、参考、日志、脚本、说明或相应子目录。替换前按用户最新范围处理旧图：允许归档则放项目归档；明确删除则核对范围后删除、不另造备份。未授权永久删除时采用可恢复归档，不额外清理其他项目。文字记录与图片清理分开，不能用“必须备份”抵消明确删除要求。
- 收尾核对标题与实际文件一一对应、无额外文件／子目录、当前图片可读、引用可达，并报告实际新生成／复用／修复／旧版处理及真实原生尺寸。助手静态验收、用户明确确认和视频动态验证分别记录；本规则不要求额外生成测试视频，也不把静态通过说成零错漏或成片已验证。

以上是可复用决策；某剧的物种、羽冠、配色、眼睛比例、服装数量与资产总数属于项目标准，不写成所有项目的固定模板。仅维护或安装本Skill不触发项目重绘、旧图清理、视频或对外发布。
