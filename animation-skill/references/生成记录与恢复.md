# 生成记录与恢复

## 执行前的最小对账

查本次授权阶段／资产范围、实际渠道、已有合格母版、待决问题、已接受或未知任务及累计尝试。新Skill、新文件夹、节点或Agent不清零旧计数。更新／安装规则不恢复历史失败任务，不运行视频或其他冻结阶段。

有明确制作范围时，自主写词、修普通歧义、做可恢复的局部处理；不要求用户批准每份词或每张图。若用户明确只写词、只检查、先看一轮或先看主角样张，则只执行该范围。

## 费用、提交与等待

- 统一内置，工具未公开的具体型号与费用如实记未公开，不猜价；既有授权内直接执行，不把安装当生成授权，不切换外部入口或扩大调用范围。
- 不充值、买套餐、切模型／平台／规格或扩大精确次数。用户指明更窄轮数时服从更窄范围。
- 每项先保存执行词、参数、参考输入与职责、需求键及稳定唯一request-id，再提交一次。幂等是客户端防重复能力，不宣称平台全局永不重复。
- 接受后用真实任务ID查询，不通过重发等结果；轮询期间推进其他已授权独立工作。CLI退出0、HTTP成功、accepted、排队卡或空URL不等于图成功。
- 超时、断线或非预期响应为未知时，先查原回执、任务、产物和消耗；对账前不换request-id重发。
- 内置每个不同资产独立调用；等待较久时给简短进度，不用重复调用来确认是否运行。工具具体型号和费用未公开就记录未公开。

## 成功后的真实核验

只保存任务真实返回、正常授权路径可获取的原图，下载不带API凭据，不绕过会员、水印或安全访问规则。核对实际文件存在、解码、尺寸和来源，再实际看图。原图、预览图、编辑图、裁切与放大明确区分。

记录最少必要字段：需求键、渠道与实际模型、词版本、参考列表／职责、参数、request-id／task-id、提交／成功状态、候选与采用文件、原生及交付尺寸、是否后处理、观察、接受次数、费用或未知。签名URL与凭据不放便携交付包。图片可看但结构错误不能标可用；结构正确且未让用户定版时也不能写“用户已选定”。

## 有界恢复

1. 首次失败先判断网络／参数／模型能力／任务审核／缺图或实际视觉缺陷；通用报错不假定唯一原因，先复用已有合格结果。
2. 授权与预算允许、且确有新依据时，同一需求首次之外最多再接受2次生成或编辑；计数跨渠道、版本、会话与Agent共享，未知先对账。用户规定只一轮时不自动补两次，旧限制不因新需求名称清零。
3. 每次只针对实际缺陷修词、纠正参考职责、局部编辑或采用已授权可行构图。不得删掉必要剧情／身份／结构、绕审核、降低标准或静默换渠道求成功。
4. 有合格结果立即停止；没有更可靠方案、硬阻碍或次数用尽时，报告缺什么、为什么、已有产物和下一步，继续其他独立项。不把“再试一次”作为无限默认。
5. 用户明确提出新画风／需求或新试验时，记录需求变化及新授权边界，历史尝试照留；不是借新试验自动获得全剧重绘额度。

## 交付

提供可看图页面／原图入口、完整实际词、版本和真实结果。保留首轮、修正版、候选与失败的真实执行记录；用户要求删除图片时只保留允许的文字与清理事实，不借“可追溯”强留图像副本。当前索引指向最新最终图，历史记录不冒充当前版本。更新上游母版只检查实际依赖；用户另要求全套复检时按[资产反馈修订与全套复检](资产反馈修订与全套复检.md)逐图完成，修复返回后实际复看。

三类资产文件夹仅保存最终图，一项一个正式文件，候选／输入参考／过程／日志／脚本不得放入或建子目录。必要文字记录与用户允许保留的过程放项目归档，用户明确删除旧图／过程时按其范围删除，不另造图片备份；执行记录保留当时路径与删除事实，当前索引指向现存最终图，看图页不挂已删除图片。此规范不授权额外清理别的项目或无关目录。

无真实图不编路径／哈希，无真实图参考不称已锁风格，未核账不把feeCost或currentAvail直接当人民币。结构／流程校验不等于审美保证、动态通过或内容零风险。
