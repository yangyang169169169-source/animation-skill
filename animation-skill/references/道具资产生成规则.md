
客户正式剧本完成校对、确认并通过安全检查后，为全剧反复出现、承担剧情功能或需要特写的关键道具生成独立概念图。已有角色和场景资产可提供比例、时代与材质参考，但不是硬前提。开始前必须确认权威剧本和现有道具资产状态；不得依赖固定项目状态卡或某台电脑上的目录。道具图只服务剧情识别、连续性和镜头复用，不为凑数生成泛化小物。

先读取同目录[资产规划与按需生成规则](资产规划与按需生成规则.md)、[内置提示词与执行](内置提示词与执行.md)、[色光与材质基准](色光与材质基准.md)及[场景道具英文文字规则](场景道具英文文字规则.md)。道具统一Codex内置，按用户／项目有效美术保持画风、形状、材质与光色，同物件派生引用结构母版。完整登记实例、状态与去向；分级和是否出图分开判断，只有需要图片的条目进入生成清单。

### 固定目录与命名规范

道具概念图相关文件采用与角色、场景资产一致的简洁结构：

```text
[项目剧本目录]/
├── prop_prompts.md
├── prop/
│   ├── 01_LotusCoin_01_HeroCloseup_Ep01-50.png
│   ├── 02_PregnancyTest_01_PositiveResult_Ep01-03.png
│   └── 03_SealedContract_01_TornCorner_Ep08-20.png
└── 归档/
    └── YYYYMMDD_HHMMSS_[简短原因]/
```

* `prop_prompts.md` 直接放在项目剧本目录根部，为唯一当前道具提示词文件；修改前的旧版只进归档，不在根目录保留多个权威版本。
* 道具最终图片统一放入项目剧本目录下的 `prop/` 文件夹；该目录只保留最终图，不放候选、过程、参考、展示副本、脚本、日志或说明，也不建相应子目录。临时与必要记录在资产目录之外处理；用户明确删除旧图时按其范围执行，不另造图片备份。
* 道具图片统一命名为 **`道具编号_道具名_变体编号_变体名_第几集.png`**，例如 `01_LotusCoin_01_HeroCloseup_Ep01-50.png`。
  * `道具编号` 必须与 `prop_prompts.md` 中的道具资产序号一致，使用两位数字。
  * `道具名` 使用无空格英文 Slug，避免空格和特殊符号。
  * `变体编号_变体名` 用于区分完整/破损、正面/背面、使用前/使用后、普通/关键特写等必要视觉变体；没有明显变体时统一使用 `01_MainLook`。
  * `第几集` 使用 `Ep01`、`Ep01-08`、`Ep36-50` 等格式。
* `prop_prompts.md` 生成清单中的每张计划图片采用同一套编号与集数命名，标题是最终图片文件名的无扩展名版本，最终图片文件名 = 条目标题 + `.png`。免生成状态、C级归属和纯排版任务留在规划表，不建立待生图条目。
  * 条目标题格式：`### 01_LotusCoin_01_HeroCloseup_Ep01-50`
  * 条目字段只保留：`涉及场次`、`Prompt`
  * 不在每个条目重复标题已有编号、名称和集数；实例流转、分级、归并理由、制作方式及母版参考放规划／调用表。实际生成派生图时按表传入真实母版参考，不只在 Prompt 中写“同一件物品”。
  * 连续集数用半角连字符，例如 `Ep01-08`；中间断开的非连续集数用中文顿号，例如 `Ep01、Ep08、Ep12`，不得用 `_`、`+`、逗号或虚假连续范围。
  * `涉及场次` 只写场号并按剧本顺序用中文顿号连接，例如：`1-2`、`2-1`、`8-3`；场号已有集数，不再加 `EpXX：`、剧情说明或道具动作。
* `prop_prompts.md` 语言规范：除道具英文名或道具 slug、条目标题、最终图片文件名、图片路径、`Prompt` 正文及准确引用的剧情所需英文文字／译文外，其他字段名、说明文字、调研摘要、整合说明、归并原则和检查结论必须使用中文。
  * 不得在 `Prompt` 正文之外使用 `Prop ID`、`Variant ID`、`Coverage`、`Suggested Filename`、`Description`、`Merge Reason`、`Lighting Plan` 等英文元信息字段。
  * 道具名作为文件名 slug 时可用英文；解释道具功能、持有人、状态变化、时代依据、材质工艺和剧情用途时必须用中文。
* 返工前将受影响的 Prompt 旧版及旧图片归档到 `归档/YYYYMMDD_HHMMSS_[简短原因]/`，不覆盖备份。已有日志则追加，否则在交付说明记录；不强制创建大纲或项目状态卡，只更新受影响物件及依赖状态。

### 第一阶段：道具清单整理 + Prompt 文件生成（必须先行）

先完成可审阅的规划及生成 Prompt，再按已获授权执行；未获本轮生成授权时先确认，不重复申请已有授权。

1. **完整通读正式剧本**：必须逐集阅读完整正式剧本，提取所有被人物拿取、使用、传递、争夺、隐藏、展示、损坏、签署、识别或作为证据出现的道具。

   * 不得只扫描道具名关键词，必须结合剧情判断道具是否承担叙事功能。
   * 必须特别关注：信物、合同、婚书、遗嘱、徽章、钥匙、药瓶、照片、检测报告、账本、武器、首饰、硬币、食物、宗教/仪式物、科技设备、交通载具局部、手写信、菜单、票据、奖杯、制服标识、家族纹章等。
   * 不得把大场景本身当作道具；桌椅、门、墙、普通餐具等若只是场景陈设，默认并入场景图，不单独出图。
2. **道具功能分级**：根据剧情功能将道具分为 A/B/C 级，避免资产失控。

   * A级：承担身份识别、证据、信物、反转或结局回收等关键作用，哪怕只出现一次也保证充分设计和可靠表现；可通过已有母版、独立图、局部或精确排版实现，不等同于必须调用生图。
   * B级：需要稳定外形、特写或独立合成的支撑道具，按现有资产能否覆盖决定出图。
   * C级：可由场景或镜头描述充分承载的普通小物，只登记归属。可见、拿过或反复出现本身不触发独立出图；确需特写／合成时说明具体用途并升级，再进入生成清单。禁止先列C级又追加完整生图 Prompt。
3. **道具流转与状态连续性表（必须先行）**：逐场记录 `道具 | 剧情功能 | 首次场次 | 当前持有人 | 交接/遗失/取回 | 状态变化 | 最终去向 | 是否出图`，避免同一物件凭空出现、重复持有或前后视觉不一致。

   * 完整、破损、沾血、签字、开合、发光、被夺走、修复等状态分别登记发生、持续与消失条件，再判断母版＋镜头处理、局部／组件或必要派生图能否覆盖。
   * 新图须有剧情、用户或美术／制作依据；不得为凑数量生成没有实际收益的相似版本。关键断口、结构变化、多角度接触和反复证据特写可保留必要参考。
   * 道具的尺寸、材质、颜色、纹理、年代工艺、磨损程度、标记位置和可识别视觉锚点必须保持连续。
   * 使用已有合格母版，确需新图时先验证基础外形；实际需要的派生图引用该母版及必要前态，只改变指定部分。免生成状态仍锁定缺口、签名区、封蜡、污渍或纹样，不能遗漏，也不生成每种状态排列组合。
   * 载具外观作为道具资产，车厢/驾驶室等可表演内部空间作为场景资产；两者必须共享车型、年代、颜色、材质、门窗和标记锚点。
   * 非人物件按[物种生活方式与世界联动设计](物种生活方式与世界联动设计.md)明确使用者、接触／握持部位、支撑、相对尺寸、动作及结果，再设计外形；不只给普通人类工具贴物种纹样。写字、休息、照护及运输设施保必要功能，私人、客用与医疗实例不自动合为一件；无独立图片用途时仍由场景承载。
4. **道具时代与材质调研（必须先行）**：在写道具 Prompt 前，必须根据故事时代、地区、阶层、职业、宗教、行业和生活方式做资料调研，优先联网查证真实道具的材料、形制、工艺、纹样、包装、文字系统和使用方式；若当前环境无法联网，必须基于剧本设定和已有资料明确说明调研限制。

   * A级道具提炼足以支持辨认和复用的设计锚点，如材质、纹样、封印、刻印、开合和包装结构。数量服从物件用途，不为达到锚点数添加剧情不需要的复杂装饰。
   * 道具设计必须切合角色身份和时代背景。贵族、王室、财阀、神话、宗教、科幻、高端品牌类道具可以更精致华丽；底层、平民、战争、生存、边境类道具也必须有独特细节，而不是只写“普通旧物”。
   * 合同、报告、信件、票据、包装、屏幕或刻字需要表达剧情信息时，允许直接生成准确英文，按共用文字规则落实来源、精确内容、位置和可见状态；不为加字本身另要许可，也不一概留白或强制后期。长篇／微小文字或真实工具限制使内容无法可靠呈现时可采用可控排版／合成，记录未完成部分；未签／已签、屏幕开／关和不同正文按状态共享载体，不各生一件物品。关键人名、日期、金额、编号和结论不得编造。
   * 每个时代道具 Prompt 同时写入正向时代锚点和错误年代负向词。禁止用 `old`, `vintage`, `transport truck`, `medical device` 等泛词代替具体年代、地区、结构和材质。
5. **中颗粒度道具归并**：在生成 Prompt 前，必须把原始道具归并为“可复用道具资产”。

   * 分开**剧情实体与流转、基础外形、镜头状态**。同物件功能或持有人变化不新增外形母版；不同实例可共享视觉设计，但不能合并其身份、数量、证据链和流转。
   * 可以复用：同一戒指的佩戴、展示与交接，同一合同的签字前后，同一设备的屏幕状态。外形相同的两瓶水若被调换，仍分别记录两个实例。
   * 状态差异必须明确记录，不等于必须拆成多张 PNG。浅表血迹、污渍、微光、签名优先评估状态／组件／排版；碎裂、明显形变、关键断口或复杂开合保留必要参考，不为省图破坏剧情辨识。
   * 按实体、外形母版、派生图、组件和免生成状态分别统计，不按集数预设数量范围。普通物件不能因出现次数多自动升级，短暂关键证据也不能因出现次数少被省略。
6. **生成 `prop_prompts.md` 文件**：在项目剧本目录根部生成 `prop_prompts.md`，文件顶部必须先写道具调研摘要、道具整合说明和关键道具连续性表，再列出资产道具 Prompt，按已有授权与审阅安排执行，未获生成授权才确认：

   ```markdown
   ## 道具视觉调研摘要
   - 故事时代与地区：...
   - 核心材质与工艺锚点：...
   - 阶层/职业/宗教/行业相关道具特征：...
   - 文字、标识与可读内容处理原则：...
   - 需要避免的泛化道具写法：...

   ## 道具整合说明
   - 原始剧本道具数：XX
   - 实体数：XX；外形母版：XX；必要派生图／组件：XX；免生成状态：XX。
   - 归并原则：实体流转与视觉母版分开，状态记录完整，按镜头需要决定出图。
   - A/B/C级：在调用表登记分级与制作方式，C级不进入生成清单。

   ## 关键道具连续性表
   | 实例与级别 | 剧情功能／场次 | 持有人流转 | 状态及持续条件 | 最终去向 | 母版与制作方式／依据 |
   |---|---|---|---|---|---|
   | Lotus Coin，A级 | 神迹信物，实际场号 | Aarav → Mira → Aarav | 普通硬币 → 微光，按触发启停 | Aarav收回 | 1个外形母版；此例微光用后期，难以实现时补局部参考 |

   ### 01_LotusCoin_01_MainLook_Ep01-02、Ep08
   - **涉及场次**：`1-2`、`2-1`、`8-3`
   - **Prompt**：`[组装好的完整可复制提示词，不得写“道具描述 + 道具 Prompt 后缀”；Prompt 内已包含道具功能、材质工艺、尺寸比例、横版16:9比例、视觉锚点、光线方案和负向词]`

   ```

7. **生成前审阅**：将完整 `prop_prompts.md`、生成清单及免生成去向准备好；未获本轮生成授权时交用户确认，已有授权则在其范围内执行。

### 第二阶段：执行生成

**画风硬要求**：每条实际内置道具Prompt明确指定动画风格和真实输入职责，落实造型、比例、材质／笔触、配色与光照，使道具精良并与人物／场景同一世界。用户或项目有效图作美术参考；关联衣装、头饰或尺寸时引用正确本人的图，不带入人物。结构、数量、证据与用途必须成立；质感漂亮不能放行错误物件，也不用写实产品照替代动画画风。生成前核对词、生成后与实际风格图并看，返修沿用已有边界。

1. **实体道具图模板 (Standard Prompt Template)**：仅用于实际需要的实体图片。局部、纹样组件、屏幕 UI 或纯排版按用途制作，不套用完整物件的动画道具渲染模板。

   ```text
   [道具描述], 16:9 horizontal aspect ratio, landscape composition, centered isolated animated-feature prop design, coherent with the supplied project style reference, accurate silhouette and story-specific construction, tactile stylized materials, refined craftsmanship, clear material separation, soft directional light and readable shadows, balanced exposure, complete object visible, no people, hands, characters, unrelated objects or watermark; include only the exact story-required English text and markings specified for this object, with accurate spelling, numbers, placement and current state, and no invented wording or unrelated labels.
   ```

   **模板变量说明**：

   * `[道具描述]` = 包含道具名称、剧情功能、时代地区、材质、尺寸比例、工艺、纹样、磨损状态、状态变化、可识别视觉锚点和必要光线方案的具体描述，不能只写“一个戒指”“一份文件”“一把钥匙”等泛化词。
   * 实体母版保留完整轮廓、清晰尺度材质、隔离主体和明亮动画材质渲染要求。局部参考按需要取景，组件／排版按实际载体选择尺寸与输出格式，不为套模板生成无用整物图；实际像素与放大情况按共用规则记录。
   * **最终交付完整展开铁律**：上述模板和固定后缀只能作为 AI 内部组装规则，严禁在 `prop_prompts.md` 中定义“道具 Prompt 后缀”后让每条 Prompt 写 `+ 道具 Prompt 后缀`。每个道具的 `Prompt` 必须是一段已经完整展开、可直接复制进出图工具的完整文本。
2. **生成要求**：

   * **单一道具主体**：每张图默认只生成一个核心道具，或一组不可分割的成套道具。不得生成手、人物、背景群众或无关杂物。
   * **画幅与用途**：实体概念图默认横版16:9，在 Prompt 中写明比例与主体布局。纯排版、局部和组件使用适合最终载体的画幅与裁切，不拉伸物件或为了全图比例裁掉关键部位。
   * **干净可复用构图**：默认使用中性影棚表面、清晰边缘、完整轮廓，方便后续抠图、合成和特写使用。
   * **动画材质与结构可信**：必须写明木、金属、纸张、布料、陶瓷、玻璃、皮革、石材、食物、电子屏等具体材质和纹理，区分不同材质的动画触感与反光，避免廉价塑料或低成本道具感；剧情明确为玩具／塑料则保留相应材质，不以风格化牺牲关键结构。
   * **状态明确**：若是破损、染血、烧焦、签字、开封、发光、旧化等状态，必须写明状态来源和视觉边界；不得把普通版默认生成成剧情损坏版。
   * **文字控制**：允许图中出现匹配剧情需求与表达的准确英文。把真正需要的字串、载体位置、字体／工艺和状态写入实际Prompt，不刻意加字，不使用与所需文字冲突的一概禁字后缀；无需求时保持物件原本的无字设计。合同、报告、菜单、证件等逐项核对正文与状态，不凭版式像文件或英文看似可读就通过，详见[场景道具英文文字规则](场景道具英文文字规则.md)。
   * **比例与尺度**：写清符合剧情的尺寸、常见规格或相对比例。区别用户／剧情规定与美术选值；不把无依据的精确毫米或食物颗数当硬性返修门槛。需要精确数量时写清总数及各子组，避免总数与追加数量歧义；标准道具母版不添加无关参照物。
   * **光线清晰**：道具图默认明亮通透、结构可信、有统一动画长片级材质质感；暗黑、低照度、强剪影会降低后续合成可用性，默认禁止。
3. **执行流程**：

   * 使用内置image_gen，明确风格／材质图不用于复制人物或建筑，实际道具母版控制形制／状态，关联人物图只控制对应尺寸／衣装材料；不得换错角色或带入背景人物。按已获授权先复核或建立核心物件母版，确认时代、尺度、材质、轮廓与文字后再扩展必要派生；已可用母版、C级归属和后期任务不自动进入生图批次。
   * 每张道具图必须严格使用 `prop_prompts.md` 中对应道具的完整 Prompt，不得临场简化或擅自添加人物。
   * **交付前残留扫描**：写入 `prop_prompts.md` 后，必须全文检查并清除以下残留：`+ 道具 Prompt 后缀`、`+ 后缀`、`道具 Prompt 后缀`、`[道具描述]`、`[组装好的完整提示词]`、`[组装好的完整可复制提示词]`、`标准提示词模板`、`固定后缀段`、`拼接`。若发现残留，必须先自动展开为完整 Prompt，再交付给用户确认或执行生成。
   * **命名完整性扫描**：写入 `prop_prompts.md` 后，必须逐条检查每个道具条目标题是否包含两位道具编号、道具名、两位变体编号、变体名和 `Ep` 集数范围。若缺失编号、变体编号或集数，必须补齐后再交付。不要为这些信息额外增加重复字段。
   * **涉及场次扫描**：每个道具条目必须有且只有一行 `涉及场次`，只列该道具及对应状态在正式剧本中实际可见的场号，并与标题集数一致；纯对白提及、画外说明或未展示的文件清单不计入。
   * **中文元信息扫描**：写入 `prop_prompts.md` 后，检查 `Prompt` 正文之外的内容。道具英文名／slug、条目标题、图片文件名／路径及准确引用的剧情英文目标文字可以保留；其余元信息用中文，英文说明或重复英文字段改为中文，不能误删待上图的准确英文原文。
   * **道具连续性扫描**：写入 `prop_prompts.md` 后，必须检查同一道具不同变体之间的尺寸、材质、颜色、纹样、破损位置、封印位置和核心视觉锚点是否连续，并核对持有人流转和最终去向。若出现同一物件像完全不同道具或凭空转手，必须先修正 Prompt/台账再执行生成。
   * **母版引用扫描**：实际生成的派生图从调用表获取正确母版及必要前态，工具执行时传入这些图，只改变指定状态。免生成状态检查实体与母版绑定、触发和持续范围，不要求状态图片。
   * **分级与用途扫描**：逐项核对C级归属、图片生成清单及实际文件，不允许C级以“补齐覆盖”为由重新进入批量生成。A级精确文字可以排版完成；每张图片有独立用途，每个关键需求有可靠制作去向。
   * **时代与文字扫描**：检查交通、电子、医疗、武器、包装和印刷工艺是否符合时代；对图中所需英文逐项核对内容、拼写、大小写、标点、数字、位置、可见状态与信息时机，查遗漏、多字、乱码和虚构内容。排版／合成只在实际采用时记录，不能把它当含字道具的默认通过前提；关键文字未完成则报告缺口。
   * **动画风格与结构验收**：把实际有效基准和道具图并看，检查形状、配色、光色、材料细节密度与尺度；同时检查数量、证据文字、接口、断口、结构与状态，美观不抵消错误。只处理受影响项，过程在资产目录外管理，按[生成记录与恢复](生成记录与恢复.md)计数，验收在本步骤内完成。
   * **功能与世界联动**：对需转译的物件逐项核对原动作、长短对比／笑点、开合、滚动、声音、承托或证据等必要机制仍成立，实际接口与身体及场景匹配。已授权替换明确写入视觉说明并保原文追溯；不能为统一世界默改台词、取消车辆事件或把关键道具改成无功能装饰。静态可见不冒称持握、书写、受力或救援动态已验证。
   * **废稿归档**：迭代过程中产生的旧图或废稿，应存入 `归档/YYYYMMDD_HHMMSS_[简短原因]/` 文件夹。
4. **资产存放**：生成的图片存放在项目剧本目录下的 `prop/` 文件夹内，并严格使用 `prop_prompts.md` 中对应条目标题作为文件名主体，即 `条目标题.png`。最终图片文件名必须包含道具编号、变体编号和 `Ep` 集数范围，严禁保存为只有道具名、变体名或无集数的文件名。

若剧情修改导致核心道具新增、删除、转手或状态变化，先更新调用表与受影响 Prompt，再核对哪些图片确需编辑／重生；仅持有人或覆盖场次变化不自动改图。资产交接使用同步后的有效记录，未变化资产保留。
