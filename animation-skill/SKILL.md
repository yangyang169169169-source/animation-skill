# 动画 skill：定制动画短剧生产流程

版本：`0.8.1-episode-dialogue-completeness-20261026`。本Skill仅含以下四步，覆盖正式剧本、动画适配及三类资产；步骤1逐集检查对白数量与完整性，图片统一Codex内置。角色体态、个性化妆发、生活空间与工具联动设计，保留剧情配色、情绪影调、同衣复用及确认资产复检；场景／道具允许剧情所需的准确英文，不刻意加字。蓝本继承及本次调整见[蓝本继承与动画差异](references/蓝本继承与动画差异.md)。

## 步骤总览

1. **步骤1：项目初始化、剧本检查与最小修复、动画适配及画风**
2. **步骤2：角色概念图 Prompt 与生成**
3. **步骤3：场景概念图 Prompt 与生成**
4. **步骤4：道具概念图 Prompt 与生成**

## 定位

本 Skill 的默认输入是客户已经完成的正式剧本。目标是纠正明确错误、守住内容边界、保证生产连续性，并把确认稿转化为稳定的角色、场景和道具视觉资产。

仅维护、安装或审阅本Skill时不创建生产项目、不复制客户稿、不运行步骤2—4；项目先行规则适用于实际项目工作。只执行用户当次指定步骤和范围，完成四步后不自动扩展制作阶段。

默认不进行剧本库检索、小说改编、题材换皮、重新设计主线、重写大纲、压缩或扩写集数、强化爽点或重排结尾钩子。用户明确追加这些任务时，改用对应专用 Skill，不得在本流程中顺带完成。

## 资产提示词与画风硬要求

**动画资产必须合理、有美感，并符合本项目指定画风；提示词是实现这一要求的执行文本。** 此条同时约束步骤2、3、4的实际提交词和图片验收，不能只写在视觉总纲、文件说明或工具名称里。

- 每项完整Prompt须明确动画媒介／指定画风，并把该风格的关键形体、表情／造型语言、材质／笔触、配色与光色落实到当前资产；仅写“好看、高清、Disney/Pixar”或“模仿参考”不算完成。不同画风按其真实特征写，不能一律套3D或真人摄影词。
- 角色、场景、道具及所有必要派生统一使用Codex内置image_gen，实际方法读[内置完整执行词](references/内置提示词与执行.md)。用户指定的画风、参考与质量要求优先于工具默认审美，未指定才沿用步骤1.7的默认；不能因渠道统一降低设计、细节或实际验收。
- 步骤1.7及步骤2—4新批次先读[制作前参考研究与质量对标](references/制作前参考研究与质量对标.md)：项目开头人物／场景图管已指定的画风、造型与质感，另行指定的影调／色调来源在色光维度优先。制作前按当前缺口联网查阅并实际看对标作品，有效研究可复用；将长片完成度具体转成毛发、五官表情、织物、空间与材料层次，再用真实图检查，不只堆“高清／工作室名”，不把栩栩如生改成真人写实。
- 每部剧首次制作资产前再读[迪士尼皮克斯作品匹配与近期工艺](references/迪士尼皮克斯作品匹配与近期工艺.md)：根据正式剧本的主题、形式、年龄／物种、关系与世界设定选择主要设计参考，另核对近期可用作品的工艺；优先合适新作，经典可借设计，不将旧完成度作为质量上限。研究原作／续作与真实素材性质，统一本剧人物、场景、道具的形状语言，不能每部都套同一片或把多个片名混成万能后缀。
- 合理与美感同时落实：人物比例、五官／物种结构、神态和服装协调且有辨识度；场景尺度、建筑、陈设与光源成立且构图有层次；道具形状、材料与关键结构准确且造型精良。不得为美化改物种、年龄、体型、身份、剧情或证据。
- 非人项目、新世界或拟人程度调整按[物种生活方式与世界联动设计](references/物种生活方式与世界联动设计.md)统筹身体、个性化修饰、居住通行、家具和工具；自然形体不等于全员素颜同型，生活特色不靠给人类空间贴物种装饰。世界转译保住剧情动作、接触与证据；用户已授权的替换直接落实，不扩张成所有项目默认。
- 场景和道具资产允许出现英文文字，但必须由剧情需求或表达功能决定，内容、拼写、数字、位置和当前可见状态准确；不为装饰、显专业或填空刻意加字。有需要的文字直接进入实际生成词并验图，不再默认一概禁字或强制后期，详读[场景道具英文文字规则](references/场景道具英文文字规则.md)。
- 角色先按剧本物种设计，包括但不限于人类、动物、植物和外星生物。先确定固有形态、拟人程度、支撑／运动／操作方式与表情载体；没有的头颈、五官、四肢、服饰不为套模板补出。参考同类优秀动画／动画短剧并原创转译，具体研究及无头角色特写规则见步骤2所引角色参考。
- 新身份必须读取[角色剧情驱动与造型差异](references/角色剧情驱动与造型差异.md)：从剧情证据设计头脸、五官布局、毛发／发型发色、眼神眼妆、自然表情与身形，按真实物种适配。先拉开脸身底层，再安排妆发和衣装；不靠眼色、妆容、衣色或表情标签掩盖同一底子。用户图仅借色调时不绑定其身份。
- 内置使用完整结构化英文词，写清每张实际参考的职责；新角色独立建身份，同人派生锁本人脸身、本色与纹样。色光依[色光与材质基准](references/色光与材质基准.md)落实：白底展示保准确本色，剧情场景依情绪与实际灯源组织冷暖明暗，不全员染黄或加紫影，也不套既往项目的固定暖色。执行词保留必要设计与剧情证据，不套其他工具的正文长度或参数规则。
- 生成前逐条核对“画风有没有进入实际提交正文、具体视觉特征是否与之相符”；生成后看真实图，分别检查画风、合理性／美感和身份／结构。风格明显偏离或形体结构错误不能标为静态可用或定版，不以漂亮、像真人、高清或文件齐全替代通过。
- 只在既有授权与有限返修范围处理真实缺陷；无可行方案或次数用尽则报告具体缺口，不能无限重画，也不因本规则自动返修历史资产。

**内置质量对标用户所选方向，不以工具默认结果作验收下限。** 对3D长片方向，真实图应具备协调但独立的脸身、清楚眼睑与目光、分组有层次的毛羽、可信的毛流与发型、可读的妆感与自然表情、贴合体量的衣装、精细但有主次的织纹／针线／金属及通透色光。用户所选参考的关键优点须进入实际正文和看图核对；模糊毛发、统一模板脸、缩水体量、衣料糊成塑料、颜色单薄或结构错误均不能只凭“是内置图”或“文件已生成”通过。参考只借明确优点，错误结构不传播；以原授权和有限返修处理，不承诺一次或仅凭文字就达到成片级效果。

资产首次生成仍按步骤2—4；用户调整已有资产、确认新样张、要求批量同步或更新后复检时，另读[资产反馈修订与全套复检](references/资产反馈修订与全套复检.md)。按身份、发型、服装、质感和光色分别落实最新明确决定，先处理会扩散的母版问题，再更新授权内的实际依赖。单张待确认不自动批量替换；全套复检逐图看内容并核对覆盖、命名和最终目录，不用文件数量或哈希代替看图。

**人物群像须在同一世界里有清楚区别。** 主要角色、重点配角和常同框功能角色先拉开头脸五官、身体比例、头部轮廓，再按设定使用固有毛羽／肤色区、纹样和适合男女角色的个人／职业配饰；衣色、妆色和临时表情不能代替身份。实际并看头像与完整身体，并把识别点延续到本人换装，详见[角色剧情驱动与造型差异](references/角色剧情驱动与造型差异.md)。服色按剧情、人设和场合组织主辅关系，主配角协调；过浓时适度降饱和、提明度，必要舞台与仪式仍可鲜艳，不固定全员高饱和或灰淡，详见[色光与材质基准](references/色光与材质基准.md)。同一衣物跨集、修补和轻微状态优先复用；真正不同的设计须有可读区别，不人为添差异保重复图，详见[资产规划与按需生成规则](references/资产规划与按需生成规则.md)。

**差异化与高质量必须服务本剧。** 不同类型动画均按各自物种、世界与人物经历设计；人类的肤色／族裔、脸型、身高体态、五官和个人风格，转译为非人角色真实存在的本色／纹样、种属或族群、核心体块、身体尺度、表情结构及适用配饰，不能只把同一人形模板换动物头。每个需要观众辨认的角色都有个性，剧情要求的相似性保留。不同场景同样按地点、使用者、职能、文化和空间特征建立身份，影调服从剧情情绪、实际时段与灯源；统一画风不要求所有空间同布局、同颜色或一律温暖明亮。具体落实在步骤2与步骤3，实际验图同时查设计特色、剧情准确和后续镜头可用性。

## 全局规则

1. **项目先行**：除非用户提供的文件已经位于符合命名规范的现有项目目录中，否则任何校对、修改或资产整理开始前，必须先执行步骤1.0创建项目文件夹并归位客户原稿；不得把输出散落在下载目录、聊天临时目录或工作区根目录。
2. **权威顺序**：用户本轮明确要求 > 用户指定的正式剧本正文 > 剧情因果与连续时空 > 动作和对白证据 > 场景标题、服装颜色和旧资产标签。大纲、人物小传等辅助材料与正式正文不一致时，一切以正文为准，不因辅助材料版本较新或标注“已确认”而反向改正文，也不把此类差异交用户重新选择。AI 生成的标题或描述只能作为线索。
3. **按影响分流**：默认直接修正无争议的语言格式及不改变剧情、对白意图的轻微错误；仅把重大硬伤、实质性取舍和较高内容风险集中交用户判断；可改可不改的默认保留。用户明确要求本轮只检查、不修改时，遵守只读范围。既有明确授权不重复确认。
4. **最小改动**：尽量保留母本情节和对白。直接修正不得改写事件、人物关系、信息释放、对白意图或打点；实质性修复按已获授权处理必要连锁影响。不借校对之名润色全剧、增加支线或调整节奏；影响很小且不改也无妨的保留。
5. **修改前备份**：原地修改 Skill 或项目关键文件前备份。Skill 备份到自身 `backups/`；项目文件备份到项目 `归档/YYYYMMDD_HHMMSS_[原因]/`，不覆盖旧备份。若用户要求输出新版本文件夹，保留完整原版并在新文件夹更新即可，不覆盖原目录。
6. **剧情权威与美术设计**：确认修复后的正式剧本是下游剧情事实依据；用户认可的视觉设定和符合剧情、人设、故事背景的美术设计补充款式、剪裁、配色等未写明的细节。归档稿、旧 Prompt 和旧图片不得反向覆盖正式稿。
7. **下游失效**：正式剧本或已确认母版发生变化时，按依赖关系标记受影响的 Prompt、图片与资产调用记录为 `STALE`，核对后更新需要修改的部分。只改覆盖场次或文件名不触发图片重生；修复某套服装也不自动使该角色全部服装失效。
8. **不得用程序创作**：程序只可读取、统计、查重、校验、重命名和扫描残留，不得生成或改写剧本、资产 Prompt 正文。
9. **默认项目目录**：正式剧本和三个 Prompt 文件放项目根目录；客户原始文件放 `客户原稿/`；图片放 `character/`、`scene/`、`prop/`；制作记录和允许保留的历史放 `归档/`。
10. **制作质量第一**：先保证剧情、人设、时代地区、连续性、主要角色的吸引力与造型丰富度、实际镜头可用性，再减少无收益的重复生成与返修。新增与复用均应有叙事、审美或制作理由；不设造型数量上限、最低数量或强制节省率。
11. **需求覆盖不等于逐项出图**：步骤2—4先读取[资产规划与按需生成规则](references/资产规划与按需生成规则.md)，区分剧情实体、视觉母版、状态与生成文件。完整登记需求，仅为确需出图的项目写生成条目；免生成状态仍须进入资产调用／交接记录，不能视为漏项。
12. **审阅与授权**：在已有审阅环节一起展示新增、复用和必要参考的理由，不为按需生成再加确认轮次。用户已授权的范围继续执行，不重复申请相同权限；需要用户选择的实质性新取舍，应先准备具体方案。

用户目录补充：同一剧复用唯一正式项目，不因步骤或聊天另建人物／场景／道具磁盘项目。可见项目／聊天／任务名用“剧本中文名或清楚简称＋步骤”；用户既定完整目录名原样保留。三类资产目录**只保留最终资产图**，一项一个正式文件；候选、参考、过程、日志、脚本和说明放资产目录之外，必要文字与备份进`归档/`。用户明确删除旧图时不擅自另造图片备份。本条为后续交付规则，不授权现在删除任何项目文件。

## 步骤1：项目初始化、客户剧本检查与最小修复、动画适配及画风

### 1.0 项目初始化（所有工作的强制第一步）

#### A. 识别生产根目录

1. 用户明确指定项目目录或生产根目录时，优先使用用户指定位置。
2. 若客户剧本已经位于名称符合 `YYMM_Sx_英文剧名Slug` 的现有项目目录内，直接使用该项目，不得重复创建或再次复制整套项目。
3. 用户未指定时，从当前工作区开始扫描：优先选择其直接子目录中已经包含多个 `YYMM_Sx_*` 项目的生产根目录；若只有一个符合条件的目录，直接使用。若存在多个无法可靠判断的候选根目录，先向用户确认，不得把项目建到猜测位置。
4. 当前工作区中没有既有生产根目录时，在当前工作区下创建并使用相对目录 `TT_MassShortdrama/`。不得在 Skill 中写入某位用户的绝对路径、用户名或固定盘符。

#### B. 项目文件夹命名规范

1. 项目目录统一使用 `YYMM_Sx_英文剧名Slug`，例如 `2607_S3_TheFireCaptainTookUsHome`。
2. `YYMM` 表示项目所属月份；`Sx` 表示该月份内第 x 个周生产批次。
3. `英文剧名Slug` 优先使用客户确认的英文剧名，删除空格、标点和特殊符号，采用可读的 PascalCase。已有中英双语剧名时使用英文剧名；只有中文剧名时，根据客户剧名建立简洁、可辨识的英文工作名，不改变剧本内容。不得使用本地路径、中文标点或空格。
4. 创建新项目前，必须扫描生产根目录的直接子目录，找出已经存在的最新 `YYMM_Sx` 前缀。`YYMM` 越大越新；同一 `YYMM` 下 `Sx` 越大越新。隐藏目录、归档目录和不符合完整命名格式的目录不计入。
5. 若已经存在更晚日期的前缀，新项目必须跟随最新前缀，不得回填旧月份或旧周序的未满批次。例如即使 `2607_S5` 未满5部，只要已经出现 `2608_S1`，新项目继续使用 `2608_S1`。
6. 每个 `Sx` 批次默认承载5部剧。最新前缀下不足5部时继续使用该前缀；已有5部及以上时才进入同月份下一个 `Sx`。
7. `Sx` 上限由该月份包含的周五数量决定：有5个周五的月份可到 `S5`，只有4个周五的月份只到 `S4`。当前月份的最新 `Sx` 已满且达到上限时，进入下个月 `S1`。例如 `2607` 可到 `S5`；`2608` 只有4个周五，因此 `2608_S4` 满5部后进入 `2609_S1`，不得生成 `2608_S5`。
8. 不得只按当天日期或主观判断跳号；最终由最新已有前缀、该前缀项目数量和对应月份周五上限共同决定。生产根目录完全没有既有项目时，才使用当前本地月份的 `YYMM_S1`。
9. 若计算出的完整目录名已经存在，先判断是否就是同一客户项目。属于同一项目则复用；属于不同项目则停止并确认命名，不得覆盖、合并或擅自添加随机后缀。

#### C. 创建目录并归位客户原稿

1. 确定名称后立即创建项目目录，以及 `客户原稿/`、`character/`、`scene/`、`prop/`、`归档/` 五个标准子目录。空目录允许暂时保留，后续步骤不得另建同义目录；已有项目的其他文件和目录保留，本次规则更新不授权删除。
2. 将用户提供的客户剧本原文件原样复制到 `客户原稿/`，保留原文件名和扩展名，不覆盖同名文件，不对该副本做任何修改。客户原稿是追溯依据，不直接作为返修输出位置。
3. 后续校对、正式剧本、Prompt、图片和制作记录都必须写入该项目目录。需要修改客户稿时，先在项目根目录建立工作副本；不得直接改动下载目录、聊天临时目录或 `客户原稿/` 中的原始文件。
4. 项目创建完成后，在首次工作回报中明确项目目录、采用的 `YYMM_Sx` 前缀、该批次创建前已有项目数、客户原稿复制位置和本轮权威输入，然后才进入步骤1.1。

### 1.1 强制读取与权威确认

1. 每次执行步骤1，完整读取[步骤1校对与最小修订规则](references/步骤1校对与最小修订规则.md)、[内容安全与叙事边界](references/内容安全与叙事边界.md)、[动画可制作性](references/动画可制作性.md)及[步骤1画风与色光一致性](references/步骤1画风与色光一致性.md)。
2. 从用户指定文件和既有决定中确认权威输入、集数、目标语言及故事背景；信息已足够时直接执行，不重新询问。同目录多稿仅在权威来源实质不明时确认，不按修改日期擅选。
3. 大纲、人物小传与正式正文不同，一律以正文为准。在本轮工作副本中直接同步与正文冲突的辅助内容，归类说明即可，不列待决，不修改客户原稿和归档备份；没有大纲或人物小传时不为校对额外编写。仅正文自身的实质矛盾或不同正式正文版本的权威来源不明，才按影响判断是否需要用户决定。

### 1.2 全剧检查，按影响分流

完整通读权威全剧，并核对相关历史决定。检查范围不因报告精简而缩小：

- 重大逻辑与剧情硬伤，动机、行动、结果及关键伏笔是否矛盾。
- 对白、翻译、人物和说话人的实质错漏，身份、关系与各项秘密的知情顺序。
- **逐集对白数量与完整性**：从第1集到末集逐集统计有效角色对白条数与文本量，核对零对白、明显偏少及疑似漏写／占位；按[校对规则](references/步骤1校对与最小修订规则.md)区分现场／画外台词、旁白和中英对照，复核原文后判断。将全剧逐集表及异常依据并入现有校对说明，不能只统计全剧总量，也不为凑数编台词。
- 上下集承接、场景跳转、时间线、人物进出及伤势、服装、道具流转。
- 集数和场次完整性、语言格式、时代地区及内容呈现风险。
- 动画制作能否成立：物种／形体及既定操作结构、口型与情绪可读、服装毛羽与接触、动作重心、空间尺度、道具与证据结构、复杂交互及资产连续性。技术难点先给不改剧情的设计／镜头解法，不能因难生成删动作、换物种或改变因果。

先排除误会、谎言、回忆、原书情节、预告／回顾、刻意悬念和合理短剧省略，再判断是否真有错误。不以“更自然、更专业、更现实”为由改对白、加解释或扩写；时长只在用户要求时评估。

### 1.3 严重度与处理方式分开

| 校对级别 | 判断重点 | 默认处理 |
|---|---|---|
| E0 硬错误 | 重大事实、对白／人物错漏、关系或身份矛盾、内容缺失 | 影响剧情或需实质选择的集中待决；仅表层笔误且答案唯一时可直修 |
| E1 连续性 | 因果、知情、时空、出入场、伤势和道具承接 | 影响理解或拍摄的集中待决；局部无争议且不改变剧情的小错可直修 |
| E2 语言格式 | 错字、标点、乱码、语法、排版及语义明确的对译问题 | 有必要且不改变原意的直接修正；只是措辞偏好则保留 |
| E3 可选优化 | 节奏、爽点、审美、现实感、可有可无的解释 | 默认不改，不列待决，不阻塞交付 |

严重度依据实际影响，不按错误所在栏目判定：对白缺失或翻译错误导致关键信息改变，应升为 E0/E1；一个错字也可能改变凶手、亲属或秘密揭晓，不能当作格式直修。反过来，不为每个姓名拼写或场景标签小错索取确认。

动画技术项另记 `A-制作`，区分静态可设计、动态待验证和真实依赖，不等同于违规或必然改剧情。

内容风险另用 `S-P0/S-P1/S-P2`，按安全参考文件判断。仅制作阻断、较高风险或原文明写风险内容的特写／直接展示进入待决；无风险、低风险及风格偏好不逐条报请确认，不把角色作恶自动等同于作品违规。

### 1.4 只提交必要决定

按参考文件的精简格式输出一份校对说明：**需要用户判断**只列尚未获授权的重大问题及较高内容风险，给出前后文证据、实际影响和可直接选择的最小改法；**已直接修正**按类别概述，无需用户再逐条核实。可选优化不另列“未处理／待确认”长表。

同一根因合并一项并列全受影响场次；保留既有有效编号和用户决定。信息不足本身不构成必须提问的理由：只有影响重大且全文仍无法判断时才提问，不虚构缺失情节。不限制重大问题数量以制造精简效果。

### 1.5 最小修复、复核与交接

1. 备份本轮权威输入，在工作副本完成已授权修复及默认直修；未决重大问题保留原文，不影响其他已授权工作继续。
2. 保留总集数、事件顺序、人物关系、对白意图和结尾打点。补场景时段或纠正场号只反映既有时空，不新增剧情场次；不明且不影响剧情的时段不编造。
3. 对修复点前后复核因果、知情、人物及道具状态，并对照输入检查正文、对白及说话人的增删改。数量相同不代表内容未变。
4. 安全处理优先调整必要的镜头呈现，保留事件和后果；若仍须改动行为机制、人物关系或关键信息，先给具体方案并取得相应授权。不得以避特写为由掩盖仍存在的重大风险。
5. 逐集对白检查及全剧覆盖已完成、没有未决重大问题、复核且1.6—1.7动画适配／画风记录完成时，报告步骤1完成；合理无对白／少对白的创作例外注明依据，不据此阻塞。默认直修范围无需再增加一次“逐项批准／冻结”确认。这里的可用正式稿即下游所称“已确认／冻结稿”，已有明确只读或等待确认要求除外。
6. 存在未决重大问题时说明受影响范围，仅暂停依赖该决定的下游内容；全局因果未定时暂停相关全剧生产。未经解决的 `S-P0` 内容不得进入相应资产或视频生成。只受托步骤1时，完成后交付，不自动启动付费生成或后续步骤。

### 1.6 动画可制作性与必要调整

逐场检查身体／物种操作、头颈肩与服装结构、表演与发声、视觉年龄、毛羽／裙尾／镜面／多人交互、伤势形态、关键证据与机械接触、空间尺度、动作与台词信息容量。将源证据、受影响集场／资产、保留剧情的方案和待验证项并入步骤1校对说明，不另造一套项目状态卡。

换材质、统一肢体、用可读姿态和镜头解决复杂交互等普通设计在既有范围内执行；改变对白、身份、物种、关键动作或事件结果等实质选择先给最小方案。优先原有连续性，不因动画自动儿童化、卖萌、变喜剧或增加魔法。只有真实依赖阻塞相应部分。

涉及非人生活与新世界时读取[物种生活方式与世界联动设计](references/物种生活方式与世界联动设计.md)，将身体与操作方式、居住／通行／工作、工具与关键剧情机制并入既有总纲和三类规划。用户已明确改变的维度覆盖旧口径，其余年龄、关系、事件与信息顺序保留；不用重新审批已授权替换，也不把世界设计当作改稿许可。

### 1.7 画风确定（合并原动画步骤2）

- 已在开始制作时指定作品、画风或参考图：直接沿用，并提炼形体比例、五官表演、材质／笔触、色彩与光、细节密度和动作尺度，不重复询问是否确认。已有实际看过且有效的参考复用。
- 读取[色光与材质基准](references/色光与材质基准.md)，将画风／工艺、角色固有色和剧情照明分开。未另指定的白底展示可沿用柔和暖中性基准；剧情场景按情绪、环境与光源安排冷暖明暗，不能把某项目的奶油暖白、暖木／香槟扩为所有新剧的统一影调。不把风格参考的脸身复制给全员。
- 未指定：可主动简短询问是否有偏好，同时推荐少量有区别的方向、适合原因及真实可见参考图；**未另获风格指定时优先按迪士尼／皮克斯式优质动画长片方向**。明确告知采用的默认，不把可选偏好问题变成无期限等待；用户明确要求等其选风格或先看方案时才暂停依赖生成。
- 不把“迪士尼／皮克斯”写成万能后缀。按本剧年龄、题材与物种形成可执行设计，默认强调角色吸引力、可读轮廓、丰富有主次的颜色、细腻材质和有情绪的光色；用户指定其他风格时完全服从其指定。
- 本轮视觉口径写入校对／交付说明；步骤2进一步放入 `character_prompts.md` 最前面的全剧人物视觉总纲，步骤3／4引用同一口径。不强制另建视觉总纲文件或增加目录。
- 全部角色、场景与道具用Codex内置建立并延续高质量动画资产。风格、色调／材质、角色身份和体态母版各司其职；用户所选方向作为设计与真实看图的基准，不复制其人物底子。具体写法读[内置提示词与执行](references/内置提示词与执行.md)。

## 步骤2：角色概念图 Prompt 与生成

执行本步骤前读取共用的[资产规划与按需生成规则](references/资产规划与按需生成规则.md)、[角色资产生成规则](references/角色资产生成规则.md)、[人物选角与跨剧差异化](references/人物选角与跨剧差异化.md)及[内置提示词与执行](references/内置提示词与执行.md)。新主要角色先根据剧本、人设和步骤1画风形成动画角色设计方向，联网查找并实际查看优秀动画人物／生物和相应造型参考，提炼轮廓、眉眼、口鼻／喙、头部附属结构、气质与表演优点，再原创转译；不直接套默认美女／俊男脸，也不把动画动物变成人脸。真实人物可作表演与比例研究，不保留真人摄影出图要求。

完整保留蓝本的全剧人物视觉总纲、选角参考与原创转译、角色视觉主菜卡、至少五项可见脸谱差异、跨剧主演对照、服饰调研、精准换装与状态调用、三联母版、命名与中文元信息、末尾出场字卡。非人角色将鼻唇、头发等不适用维度转为物种对应结构；明确同种同色设定优先。未被剧情锁定的自然毛羽色区、体态与个人配饰可用于原创区分，不因同物种强制同底子；不换物种、不削瘦规定体量、不把某剧的羽色方案推广给全部项目。

**先锁物种与形态，再研究和写词**：在既有视觉总纲／主菜卡中记录剧本依据、物种／形态阶段、拟人程度、稳定结构、表情与移动／持物方式；动物、植物、外星及其他角色均依自身结构设计，不默认直立人形。按“相同或相近物种＋角色功能＋指定画风＋受众”查找并实际查看同类优秀或有依据受欢迎的动画短剧、动画作品及设定图，提炼轮廓、结构、材质、配色和表演优点后原创转译。查不到合适短剧时用可核实的动画／生物资料补足，不编造爆款与看图记录。具体流程见角色及选角参考，不新增独立审批或固定档案。

**每个可辨认角色独立设计**：在原视觉总纲和主菜卡内统筹种属／设定族群、肤色或毛羽鳞壳等本色、脸部或身份核心、五官／感知结构、身高体量、年龄、职业和个人风格配饰。同物种内部有个体差异，跨物种也不只换头换皮；人类族裔和非人种属不机械一一对应。造型服从剧本，非人不补不存在的五官、衣服或肢体；角色的职业生活方式须落实到实际结构与活动能力。群演按镜头异脸实例处理，不强制为每位群众额外出图。

以下眉眼、面孔、男女体型、头发、服饰和站姿要求仅在该物种与剧本确有相应结构／设定时应用。无头／无颈等角色保留两个完整形态视图，第三格改为身份核心或表情／感知结构近景，不生造人脸；在原规划表说明对应关系，文件名和条目字段不变。

**设计优先级**：剧情／时代地区／物种与身体状态 > 角色身份、职能和观众第一印象 > 与其相适配的美感、气质、吸引力及动画表演潜力。主角与核心恋爱对象在设定允许时美丽／俊美、有镜头吸引力；反派、小配角、NPC以定位和辨识度为先，不强制美型也不凭外貌判善恶。全年龄保留对应特征。

**动画版外形与画质要求**：

1. 女主应具有本剧适配的顶级动画角色美感，男主同样独立定制；不统一成大眼尖下巴，也不将迪士尼／皮克斯误作同一张脸。
2. 身高、胖瘦、强弱、肩胸腰髋和肢体比例依每人年龄、生活方式及剧本人设设计，不默认全体女性纤瘦修长、男性同样高大。其他形态按自身结构获得协调美感，不套人类腰胯或长腿。丰满、孕期、年龄、残障与剧情设定优先，不能为了美化减重或改变身体。
3. 有相应眼部结构的主要男性角色，眼神与眼睑清晰、有精神；无剧情依据不加黑眼圈、眼袋或病容，不给无眼角色补眼。不得抹去年龄和身份特征。
4. 无依据不添加伤病、病理斑痕或表面瑕疵；自然肤色、雀斑、毛羽鳞壳色区和识别纹样可依设定作美术设计，不误当脏污抹掉。非人角色不套用人类磨皮。
5. 配角与主角通过脸部／物种结构、头部轮廓、眉眼、体量与发型／冠羽等形成明显差异；亲缘或同色约束按正文处理，不只换衣或眼色。

所有角色执行对应动画画风的清晰身份／表情结构、稳定体积和有主次的表面层次，按其设定选择皮肤、毛羽、鳞壳、树皮、叶片或外星材质；有服装才写服装。避免模糊、廉价塑料、蜡像或过锐光边；移除真人RAW照片、真实毛孔、固定摄影机和禁止插画等后缀。新身份及首图验收读取[角色剧情驱动与造型差异](references/角色剧情驱动与造型差异.md)，与真实关系组图片并看；风格、脸身底层、妆发、表演分别核对，不继承参考中的结构或裁切错误。

**执行**：所有角色首母版、后续造型、状态和必要角度／特写派生统一内置；真实输入用户或项目有效风格参考，同角色派生另输入本人脸与体态母版。先完整保存英文词与参考职责，生成后在本步骤完成画风、身份、结构、三视图、服装及原图核验与有界修复；验收并入本步骤。

步骤2只生成或更新：

- `character_prompts.md`
- `character/`
- 角色相关归档和资产状态

不得顺带生成场景或道具。按步骤1.5核对正式稿可用范围，未解决的重大问题或 `S-P0` 阻断其依赖的生成内容。

## 步骤3：场景概念图 Prompt 与生成

执行本步骤前读取共用的[资产规划与按需生成规则](references/资产规划与按需生成规则.md)及[场景资产生成规则](references/场景资产生成规则.md)。按物理空间和固定布局建立母版，按镜头需要保留互补视角与必要状态参考；日夜、天气和戏剧功能变化不自动生成新空间，也不能为少出图删去必要反打或改写剧情地点。

场景全部使用内置image_gen，先保存完整结构化英文执行词；派生反打、邻接和日夜图实际输入本场母版与必要邻场参考，明确各自控制范围，不假锁布局。沿用蓝本的调研、首次出场排序、A/B/C分级、中颗粒度物理空间归并、空间／状态调用表、必要互补视角与命名规则，色光落实[色光与材质基准](references/色光与材质基准.md)。

按[场景道具英文文字规则](references/场景道具英文文字规则.md)处理本场必要的英文招牌、公告、门牌或屏幕内容：有剧情／表达用途才出现，字串、位置、工艺与当前状态准确；不刻意加字，不因空场要求禁掉剧情标识。

每个场景按剧情功能、使用者生活／职业、地域文化、物种尺度和空间结构建立可辨特色，避免通用大厅、办公室或街道只换颜色。影调由当场情绪与叙事关系决定，温暖、冷峻、明亮、低调或高反差均可有依据使用；不一律暖亮或暧昧，也不用糊黑、过曝、浓雾遮盖设计错误。保留真实日夜、天气、灯源和布局，关键动作区、计划人物脸位与证据可读；同地点情绪变化不变房间。普通植物允许，植物角色及其他人物、动物、鸟虫、镜中角色和人影禁止。生成后实际检查特色、情绪、布局、空场、画风、材料和镜头用途，不以漂亮或文件齐全代替通过。

- `scene_prompts.md`
- `scene/`
- 场景相关归档和资产状态

不得顺带生成角色或道具。按步骤1.5核对正式稿可用范围，未解决的重大问题或 `S-P0` 阻断其依赖的生成内容。

## 步骤4：道具概念图 Prompt 与生成

执行本步骤前读取共用的[资产规划与按需生成规则](references/资产规划与按需生成规则.md)及[道具资产生成规则](references/道具资产生成规则.md)。分别登记实体流转、基础外形和镜头状态，分级与制作方式分开决定；C级只登记归属，确需独立制作时说明用途并升级，不能为补齐表格自动生成。

道具使用Codex内置，按需输入用户或本项目真实有效风格／材质参考；服装关联物件用本人正确造型控制材质或尺寸，必要派生引用自己的结构母版。先写完整结构化英文词，按剧情准确落实数量、接口、断口、证据文字与状态，依[色光与材质基准](references/色光与材质基准.md)统一，在步骤4完成结构、风格、连续性和文件验收，不因漂亮放过关键错误。

按[场景道具英文文字规则](references/场景道具英文文字规则.md)把确需出现的准确英文直接写进本物件执行词，逐项验收拼写、数字、语义、版面位置与信息时机；无依据不加内容，未给定的关键事实不编造，真实无法可靠生成的文字再记录可控排版方案与缺口。

- 道具相关归档和资产状态
